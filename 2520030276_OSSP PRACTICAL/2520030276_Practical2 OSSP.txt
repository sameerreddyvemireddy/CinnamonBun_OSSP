##OSSP PRACTICAL - EXPERIMENT 1

TITLE COPYING THE CONTENTS OF ONE FILE TO ANOTHER USING SYSTEM CALLS

AIM

To develop a C program that uses the system calls open(), read(),
write(), and close() to copy the contents of one file to another. To
study the transition between user space and kernel space during
execution and analyze the system calls generated by the command cat
sample.txt.

REQUIREMENTS

1.  macOS computer
2.  Terminal
3.  GCC compiler
4.  Text editor such as nano
5.  Source file: sample.txt

STEP-BY-STEP PROCEDURE ON MAC

STEP 1: OPEN TERMINAL

1.  Press Command + Space.
2.  Type Terminal.
3.  Press Enter.

STEP 2: CREATE A WORKING FOLDER

Type:

mkdir OSSP cd OSSP

To check the current location, type:

pwd

STEP 3: CREATE THE C PROGRAM

Type:

nano filecopy.c

Paste the following program:

#include <stdio.h> #include <stdlib.h> #include <fcntl.h> #include
<unistd.h>

int main() { int source, destination; char buffer[1024]; ssize_t
bytesRead, bytesWritten;

    source = open("sample.txt", O_RDONLY);

    if (source == -1) {
        perror("Error opening source file");
        return 1;
    }

    destination = open("copy.txt",
                       O_WRONLY | O_CREAT | O_TRUNC,
                       0644);

    if (destination == -1) {
        perror("Error opening destination file");
        close(source);
        return 1;
    }

    while ((bytesRead = read(source, buffer, sizeof(buffer))) > 0) {

        bytesWritten = write(destination, buffer, bytesRead);

        if (bytesWritten == -1) {
            perror("Error writing file");
            close(source);
            close(destination);
            return 1;
        }
    }

    close(source);
    close(destination);

    printf("File copied successfully!\n");

    return 0;

}

STEP 4: SAVE THE PROGRAM

1.  Press Control + O.
2.  Press Enter to confirm the filename.
3.  Press Control + X to exit.

STEP 5: CREATE THE SOURCE FILE

Type:

nano sample.txt

Enter the following text:

Hello Sameer This is Operating Systems and System Programming Lab. This
file is copied using system calls.

Save the file:

1.  Press Control + O.
2.  Press Enter.
3.  Press Control + X.

STEP 6: CHECK THE FILES

Type:

ls

Expected files:

STEP 7: COMPILE THE PROGRAM

Type:

gcc filecopy.c -o filecopy

If no error message is displayed, the program has compiled successfully.

STEP 8: RUN THE PROGRAM

Type:

./filecopy

EXPECTED OUTPUT

File copied successfully!

STEP 9: VERIFY THE COPIED FILE

Type:

Now copy.txt should also be visible.

Display its contents:

EXPECTED OUTPUT

ALGORITHM

1.  Start the program.
2.  Open sample.txt using open() in read-only mode.
3.  Check whether the source file is opened successfully.
4.  Create or open copy.txt using open().
5.  Read data from sample.txt using read().
6.  Check whether data has been read.
7.  If data is available, write it into copy.txt using write().
8.  Repeat the read and write operations until the end of the file.
9.  Close sample.txt using close().
10. Close copy.txt using close().
11. Display the success message.
12. Stop.

EXPLANATION OF SYSTEM CALLS

open(): The open() system call opens a file and returns a file
descriptor.

read(): The read() system call reads data from the source file into a
buffer.

write(): The write() system call writes the data from the buffer into
the destination file.

close(): The close() system call closes the opened file and releases the
associated resources.

USER SPACE AND KERNEL SPACE TRANSITION

The C program initially executes in user space.

When the program calls:

open() read() write() close()

the request is transferred to the operating system kernel through the
system call interface.

The kernel performs the requested operation, such as opening a file,
reading data, writing data, or closing a file. The result is then
returned to the user program.

Simple representation:

USER SPACE | | System Call: open(), read(), write(), close() v SYSTEM
CALL INTERFACE | v KERNEL SPACE | v FILE SYSTEM / KERNEL SERVICES | v
Result returned to USER PROGRAM

SYSTEM CALL TRACING

IMPORTANT NOTE FOR macOS

The command strace is mainly available on Linux and is not normally
installed on macOS.

Therefore, if you type:

strace cat sample.txt

macOS may display:

zsh: command not found: strace

On Linux or Ubuntu, use:

strace cat sample.txt

To save the trace into a file:

strace -o trace.txt cat sample.txt

On macOS, you may try:

sudo dtruss cat sample.txt

Depending on macOS security settings, dtruss may require administrator
permission or may be restricted.

COMMON SYSTEM CALLS OBSERVED

execve() Loads and executes the cat program.

open() or openat() Opens the sample.txt file.

read() Reads the contents of sample.txt.

write() Writes the contents to the terminal.

close() Closes the opened file.

exit() or exit_group() Terminates the process.

SEQUENCE OF SYSTEM CALLS

cat sample.txt | v execve() | v Kernel loads the cat program | v open()
/ openat() | v sample.txt is opened | v read() | v File contents are
read | v write() | v Contents are displayed on the terminal | v close()
| v Process terminates

OBSERVATION

1.  The source file sample.txt was created successfully.
2.  The source file was opened using the open() system call.
3.  The destination file copy.txt was created and opened successfully.
4.  Data was read from sample.txt using read().
5.  The data was written into copy.txt using write().
6.  The process continued until the end of the source file was reached.
7.  Both files were closed using close().
8.  The contents of copy.txt were checked and found to be the same as
    sample.txt.
9.  Each system call caused control to move from user space to kernel
    space, where the operating system performed the requested service.
10. The system call tracing experiment on Linux can show calls such as
    execve(), open()/openat(), read(), write(), and close().
